# 새 메일 팝업 알림

메일 서버(MailCarrier)의 받은편지함을 주기적으로 읽어, 메신저에 **접속 중인** 수신자에게 우측 하단 팝업을 띄운다.
메일 서버 설정은 바꾸지 않는다. 기본은 꺼짐(`MAIL_WATCH_ENABLED=false`)이라 켜지 않은 서버에는 영향이 없다.

## 동작

1. 메신저 서버가 `MAIL_WATCH_INTERVAL_SEC`(기본 15초)마다 `MC7.dbo.MavInbox`에서 마지막 처리 시각 이후의 행을 조회한다.
   - 읽는 컬럼: `mm_id`, `mm_sentto`, `mm_fromname`, `mm_fromaddr`, `mm_subject`, `mm_rstime` (본문은 읽지 않는다)
2. `mm_sentto`(받는 주소)의 **@ 앞부분**을 메신저 사용자 이메일의 @ 앞부분과 맞춰 수신자를 찾는다. 여러 명이면 모두에게 보낸다.
3. 접속 중인 수신자에게 `mail` 소켓 이벤트를 보내고, 클라이언트가 팝업을 띄운다. 오프라인 사용자는 건너뛴다.
4. 마지막 처리 시각은 메신저 DB(`AppSetting.mail_watch_cursor`)에 저장한다. 처음 켤 때는 현재까지의 메일을 알리지 않고 그 이후 메일부터 알린다.

## 개인정보

- 메일 제목·보낸 사람은 수신자 본인에게 소켓으로만 보내며, 메신저 DB와 로그에 저장하지 않는다.
- 제목을 보여주고 싶지 않으면 `MAIL_WATCH_SHOW_SUBJECT=false` (보낸 사람만 표시).
- 메일 DB에는 `MavInbox`만 읽을 수 있는 **읽기 전용 계정**을 쓴다.

## 켜는 방법

1. 메일 DB(`MC7`)에 읽기 전용 계정을 만들고 `dbo.MavInbox` SELECT 권한만 준다.
2. 서버 환경 변수를 설정한다(`.env.partner.example` 참고). GitHub Actions 배포라면 Secrets에 `MAIL_WATCH_ENABLED`, `MAIL_MSSQL_USER`, `MAIL_MSSQL_PASSWORD` 등을 등록하고 deploy 워크플로의 환경 변수 전달에 추가한다.
3. 서버를 재시작하고 로그에서 `[startup] mail watch: enabled` 를 확인한다.
4. 테스트 메일을 보내 팝업이 뜨는지 확인한다. 알림은 메신저 설정의 "알림 팝업" 스위치와 방해 금지(스누즈) 설정을 따른다.

## 한계 / 다음 단계

- 팝업을 눌러도 메일 화면으로 이동하지 않는다(앱만 앞으로 나온다). 메일 바로가기는 2단계 작업이다.
- 수신자 매칭은 이메일 @ 앞부분 기준이다. 메일 주소 아이디와 메신저 계정 아이디가 다른 사용자는 알림을 받지 못한다.
- 같은 메일이 받는 사람별로 여러 행으로 저장되는 구조라면 사용자별로 한 번씩 알리게 된다(중복 알림 확인 필요).
